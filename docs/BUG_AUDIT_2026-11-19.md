# OpenPath Bug Audit & Web Viewer Redesign

Date: 2026-11-19. Scope: `src/openpath/` (Python), with the local web viewer
`src/openpath/web/server.py` as the UI target. All findings below were
reproduced by executing code (in-process render harnesses, HTTP requests, a
read-only subagent audit), not just by reading source.

## Part 1 — Bugs found and fixed

### Web viewer (`src/openpath/web/server.py`)
1. **Unrendered template placeholders (P0).** `do_GET` substituted only 4 of
   16 `{name}` placeholders in `HTML_TEMPLATE`; stats like `{total_opportunities}`
   rendered literally. Fixed with a single `.replace` chain covering all 13
   placeholders; locked down by `tests/unit/test_web_server_placeholders.py`.
2. **Silent connection drop on any error (P0).** `do_GET` had no exception
   handling, so a render error closed the socket with no HTTP response
   (`ERR_EMPTY_RESPONSE` in the browser). Reproduced on a fresh install where
   the DB had no tables (`no such table: opportunities`). Fixed: render errors
   now produce HTTP 500, unknown paths 404. Fixed DB initialization in
   `run_server` (applies migrations on startup via a connection, not the
   manager object).
3. **Latent attribute errors with real data (P0).** The card builder used
   `o.application_url` / `o.location_raw`, which are *not* fields of the
   `Opportunity` model. The local DB had 0 opportunities, masking the crash.
   Fixed to `o.canonical_application_url` and `o.locations`.
4. **Missing interactivity (P1).** The nav tabs, category filters, search
   inputs and company filter hooks had no JavaScript. Added an inline,
   dependency-free script and matching CSS states.

### Eligibility engine (`src/openpath/eligibility/engine.py`)
5. **"pre-final year" swallowed by "final year" (P1).** A naive substring
   test made the 3rd-year branch unreachable for the most common Indian
   phrasing; 3rd-year candidates were marked ineligible. Fixed with a
   negative-lookbehind regex.
6. **Degree regexes matched the words "be"/"me" (P1).** Prose like "you will
   be responsible" invented a B.Tech requirement and confirmed eligibility
   for everyone — violating the "never infer missing eligibility" invariant.
   Fixed by requiring the dotted forms B.E./M.E.
7. **"global"/"worldwide" overrode explicit region restrictions (P1).** A
   US-only remote role was reported India-eligible due to marketing copy.
   Added a negative-phrase guard; explicit residency restrictions win.

All three have regression tests in `tests/unit/test_eligibility.py`.

## Part 2 — Additional defects found (reported, not all fixed)

The read-only audit subagent reproduced these with executable probes. They are
higher-risk / broader in scope and are left for a follow-up change:

- `extraction/parser.py`: `"india" in combined` matches Indianapolis/Indonesia;
  US-only roles are stamped VERIFIED.
- `db/connection.py` + `db/migrations.py`: `executescript` implicitly commits
  inside the "atomic" transaction; a failed migration bricks the DB.
- `db/repository.py`: any crawled company string becomes a PASS-verified
  organisation; evidence timestamps are written but never read back; FTS
  `MATCH` is fed unsanitized user input (`?q=C++` throws 500); LIKE prefix
  lookups treat `%`/`_` as wildcards; `INSERT OR REPLACE` duplicates FTS rows.
- `evaluation/benchmark.py`: scorecard reports PASS on an empty DB using
  literal accuracy values; dedup metric is inverted.
- `crawler/orchestrator.py`: `--profile` is ignored; all-source failure still
  marks the run `completed`.
- `connectors/github.py`: GitHub token header built then discarded;
  `connectors/ashby.py` reads compensation at board level, not per job.
- `network/client.py`: one global lock serialises all domains; 10 MB cap is
  header-only.
- `docs/SECURITY_AND_ACCESS.md` promises robots.txt caching and the frontier
  circuit breaker; neither exists in code.

## Part 3 — Web app redesign

- Replaced the dark GitHub-CSS look with a purpose-built research-console
  palette (deep navy ground, blue accent, semantically coloured badges), a
  sticky wordmark nav, a large hero title, a five-stat rail, search bars and
  category filter tabs.
- Kept the stack (stdlib `http.server` + inline HTML/CSS/JS in `server.py`),
  all routes, data and behaviour. No new dependencies.
- Responsive grid and a mobile layout; no external assets or fonts.
